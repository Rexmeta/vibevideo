좋아. 현재 [Rexmeta/vibevideo](https://github.com/Rexmeta/vibevideo?utm_source=chatgpt.com)를 기준으로 보면, 단순히 UI를 조금 개선하는 수준보다 **“AI 영상 생성기 → AI Video Production OS”로 구조를 전환하는 프롬프트**가 필요해.

현재 프로젝트는 이미 React/Vite 기반에 Gemini/Veo, Firebase, FFmpeg, 프로젝트 복원, Job Manager, 업로드 큐까지 들어가 있어서, 전부 갈아엎기보다는 **현재 기능을 보존하면서 상용 아키텍처로 진화시키는 방식**이 적절하다. README에도 로컬/Firestore 복원 및 백필 시나리오가 상당히 구체적으로 구현돼 있다.  또한 현재 `App.tsx`가 인증, 프로젝트, Wizard, JobManager, UploadQueue, API key 상태까지 상당히 많은 책임을 가지고 있다.

아래 프롬프트를 **Replit Agent / Claude Code / Codex 등에 그대로 넣는 것을 추천**한다.

# VibeVideo Commercial Architecture Refactoring

Repository:
[https://github.com/Rexmeta/vibevideo](https://github.com/Rexmeta/vibevideo)

## Mission

VibeVideo를 현재의 AI Video Generator prototype에서 상용화 가능한 **AI Video Production OS**로 발전시킨다.

현재 기능을 제거하거나 단순화하지 않는다.

기존의 다음 기능은 반드시 유지한다.

* Project creation
* Quick / Wizard mode
* Sample project
* Express mode
* Scene generation
* Image generation
* Vision critic
* Video generation
* Gemini TTS
* Veo generation
* Project persistence
* Firebase authentication
* Firestore persistence
* IndexedDB local backup
* Upload queue

단, 현재 UI / 상태관리 / 서비스 구조가 한 곳에 집중되어 있는 부분은 상용 서비스에 적합한 모듈 구조로 점진적으로 리팩토링한다.

# 9. Provider Abstraction

현재 Google Veo에 강하게 결합된 generation architecture를 provider-independent 구조로 변경한다.

다음 interface를 정의한다.

```ts
interface VideoProvider {
  id: string;

  getCapabilities(): VideoCapabilities;

  generate(
    request: VideoGenerationRequest
  ): Promise<VideoGenerationResult>;

  getJobStatus(
    jobId: string
  ): Promise<GenerationJobStatus>;

  cancel?(
    jobId: string
  ): Promise<void>;
}
```

VideoGenerationRequest는 provider-specific parameter가 아니라 VibeVideo의 canonical format을 사용한다.

예:

```ts
interface VideoGenerationRequest {
  prompt: string;
  negativePrompt?: string;

  aspectRatio: AspectRatio;

  durationSec: number;

  resolution: Resolution;

  seedImage?: AssetReference;

  referenceImages?: AssetReference[];

  firstFrame?: AssetReference;

  lastFrame?: AssetReference;

  characterReferences?: AssetReference[];

  camera?: CameraSpec;

  motion?: MotionSpec;

  audio?: AudioGenerationSpec;

  quality?: GenerationQuality;
}
```

# 11. Model Router

예:

```text

→ Avatar / LipSync optimized model

Cinematic Shot
→ highest quality video model

→ fast generation model

Character Consistency
→ reference capable model

Camera Motion
→ camera-control capable model

→ image-to-video optimized model
```

ModelRouter interface:

```ts
interface ModelRouter {
  selectModel(
    scene: Scene,
    requirements: GenerationRequirements
  ): ModelSelection;
}
```

Selection 기준:

* quality
* cost
* latency
* duration
* aspect ratio
* reference support
* character consistency
* camera control
* audio support

# 14. Automatic Refinement

Generation 결과가 threshold 이하이면 자동으로 refinement한다.

예:

```text
Generate
 ↓
Critic
 ↓
score < 75
 ↓
Analyze failure
 ↓
Modify prompt / model / seed
 ↓
Generate again
 ↓
Critic
```

최대 retry 횟수를 설정한다.

무한 generation이 발생하지 않도록 한다.

# 26. Refactoring Rules

중요:

* 기존 기능을 한 번에 삭제하지 않는다.
* Big Bang rewrite를 하지 않는다.
* 현재 working code를 먼저 보호한다.
* 작은 단계로 migration한다.
* 각 단계마다 build/test를 실행한다.
* TypeScript type safety를 유지한다.
* `any` 사용을 새 코드에서 최소화한다.
* provider-specific code가 domain model에 침투하지 않도록 한다.
* UI component에서 API 호출을 직접 하지 않도록 한다.
* business logic을 React component에서 제거한다.

### 내가 보는 VibeVideo의 우선순위

> "프롬프트 → 영상"

을 잘 만드는 서비스는 모델 회사들과 경쟁해야 한다.
